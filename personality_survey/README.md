# Personality Test for Agents

This directory contains the tools and scripts to perform personality tests on agents using their interaction trajectories. The goal is to evaluate if the agent's personality (as perceived by the model) changes based on the context (System Prompt vs. Full Interaction History).

## Project Structure

```
personality_survey/
├── inventories/          # Directory containing personality survey items (CSV)
│   └── mpi_120.csv       # Example inventory (MPI 120 items)
├── results_test/         # Directory for test results (generated)
├── item_template.txt     # Template for formatting survey questions
├── run_personality_test.py # Main script to run the test
└── README.md             # This file
```

## Usage

The main script is `run_personality_test.py`. It requires a trajectory file (JSON) and an inventory file (CSV).

### Prerequisites

- Python 3.x
- `litellm` (for actual model queries)
- `tqdm`
- `vllm` (or compatible API endpoint) running the model

### Command

```bash
python3 personality_survey/run_personality_test.py \
  --trajectory_path <path_to_trajectory.json> \
  --inventory_path <path_to_inventory.csv> \
  --output_dir <path_to_output_dir> \
  --item_template_path <path_to_item_template.txt> \
  --model_name <model_name> \
  --api_base <vllm_api_base_url> \
  [--resume] \
  [--dimensions <dimensions>] \
  [--max_workers <num_workers>] \
  [--dry_run]
```

### Arguments

- `--trajectory_path`: Path to the agent's trajectory JSON file (generated by the agent framework).
- `--inventory_path`: Path to the personality inventory CSV file (e.g., `inventories/mpi_120.csv`).
- `--output_dir`: Directory where the results will be saved.
- `--item_template_path`: Path to the text file containing the question template.
- `--model_name`: Name of the model to query (default: `hosted_vllm/Qwen3-Coder`).
- `--api_base`: Base URL for the LLM API (default: `http://localhost:8000/v1`).
- `--resume`: If set, resumes from existing output files, skipping already processed items.
- `--dimensions`: Filter inventory by Big Five dimensions (e.g., "OCEAN", "O", "OC"). Default: "OCEAN".
- `--max_workers`: Maximum number of concurrent workers for parallel processing. Default: 1 (sequential).
- `--dry_run`: If set, skips actual model queries and returns mock responses. Useful for testing logic.

## Code Logic

The script evaluates the agent's response to personality survey items under three different context conditions:

1.  **System Prompt Only**: The model is prompted with the agent's system prompt (defining its persona) and the survey question. This establishes the baseline personality.
2.  **System Prompt + Task**: The model is prompted with the system prompt, the initial task description (first user message), and the survey question.
3.  **Full History**: The model is prompted with the system prompt, the entire interaction history from the trajectory, and the survey question. This evaluates if the personality shifts after performing the task.

### Features

- **Real-time Saving**: Results are saved immediately after each query in **JSONL** format (`.jsonl`) to prevent data loss.
- **Resume Capability**: Can resume interrupted runs by reading existing JSONL files.
- **Automatic Conversion**: Automatically converts legacy JSON result files to JSONL if needed.
- **Concurrency**: Supports parallel execution via `--max_workers` to speed up the survey.

### Data Flow

1.  **Load Data**: The script loads the trajectory JSON and the inventory CSV.
2.  **Extract Contexts**: It parses the trajectory `messages` to extract:
    - The System Message.
    - The Task Message (first user message).
    - The Full History (all messages).
3.  **Iterate & Query**: For each item in the inventory (filtered by dimensions):
    - It formats the question using `item_template.txt`.
    - It constructs prompts for all three conditions.
    - It queries the model (via `litellm`) for each prompt.
4.  **Save Output**: Results are appended to a JSONL file in the specified output directory.

## Integration with Codebase

-   **Trajectories**: This tool is designed to work with the standard trajectory format produced by the `mini-swe-agent` framework. It relies on the `messages` list within the trajectory JSON.
-   **Model Interface**: It uses `litellm` to interface with the model, consistent with how the agent itself might interact with models, allowing for flexibility in the backend (e.g., `vllm`).
-   **Environment**: It is intended to run in the same environment as the agent experiments, leveraging the same dependencies and model endpoints.
